POWER BI MODEL CLEANUP

Semantic Forge

You point Forge at a Power BI report and semantic model. It writes a Word plan of unused or unusual tables, columns, measures, and relationships. Nothing is deleted until you say yes.

Cursor MCPSetup ~ 5 minutes, onceSaves ~ 2 to 4 hours per model

What you will see

After you set it up and run it, this is what each part means.

On the screenIn simple words
Word planA list of unused or unusual tables, columns, measures, and relationships, with why each was flagged.
Shall we proceed?A yes/no stop. Yes applies the plan. No leaves the model unchanged. You can edit the plan first.
After yesThose unused objects are removed or cleaned. Visuals that still use a field are not dropped.

Who this is for

Anyone who owns a .pbip dashboard and wants a smaller, cleaner model before review.

How it works

flowchart TD A["Analyse this report and model"] --> B["Forge reads .Report + .SemanticModel"] B --> C["Complete Word plan"] C --> D["You review or edit"] D --> E{"Shall we proceed?"} E -->|No| F["Model unchanged"] E -->|Yes| G["Apply unused tables / columns / measures / relationships"]

Setup — once

  1. Open Cursor on the Semantic Forge project.
  2. Type exactly: Setup Semantic Forge
  3. If it asks for a report folder, model folder, or a login, answer once.
  4. Ask it to analyse your dashboard (daily use below).
You are done when Forge can read your report and model and offers a Word plan.

Daily use

Ask: Analyse this report and semantic model. Write the full Word plan.

Give the .Report folder and the .SemanticModel folder when asked. After you read the plan: Yes, proceed or No.

Example

Shall we proceed with the optimization? Plan highlights: - Unused measure: <name> — not used on any page - Unused column: <table>[<column>] — no visual binds to it - Relationship with no query path Yes = apply. No = stop.
